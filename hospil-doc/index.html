Installation

To install Hospil, download the template package from ThemeForest and extract the archive to your computer. Inside you will find the documentation folder and the main template folder.

  1. Extract the downloaded .zip archive to a local folder.
  2. Open the template folder — every page is a ready-to-use .html file at the root.
  3. Upload all contents to your web server using an FTP client (such as FileZilla), or simply open index.html directly in a browser to preview locally.
  4. Set index.html (or your preferred home variation) as the site's entry point.
No build step required. Hospil runs as static HTML, CSS and JS. The SASS source is provided only if you want to recompile styles.

HTML Structure

Hospil is built on clean, semantic HTML5 with a fully responsive, mobile-first layout. Every page follows the same predictable pattern, so once you understand one, you understand them all.

All editable content lives between the <body> and </body> tags. To change any text, open the relevant .html file and edit it directly — no special tooling needed. 

<!-- Typical page skeleton -->
<body>
  <!-- Preloader -->
  <div class="cs_preloader"> … </div>

  <!-- Header (top bar + nav) -->
  <header class="cs_site_header"> … </header>

  <!-- Page sections (hero, about, services…) -->
  <section> … </section>

  <!-- Footer -->
  <footer> … </footer>

  <!-- Scripts -->
  <script src="assets/js/main.js"></script>
</body>
Consistent class naming. Hospil prefixes its custom classes with cs_ (e.g. cs_site_header, cs_hero) to avoid collisions with Bootstrap utilities.

Change Images

All images live in the assets/img/ folder. To use your own imagery, simply replace the placeholder files (keeping the same filename), or update the src attribute in the HTML to point to your new image. 

<!-- Replace the file path with your own image -->
<img src="assets/img/your-image.jpg" alt="Description">
Tip: Hospil ships its photos as optimized .jpg files (icons and shapes as .svg/.png). Export your images as JPG (or WebP/PNG) and keep dimensions similar to the originals for the best layout fit. Some sections load their background from a data-src attribute (e.g. <section class="cs_bg_filed" data-src="…">) — change the path there.

Hero background video

The physiotherapy home (home-v7.html) plays a muted, looping background video in the hero. Replace assets/img/hero_bg_video.mp4 with your own clip (MP4, ideally under ~6 MB) and update the poster image, which is shown while the video loads and to visitors who prefer reduced motion. The round button lets visitors pause and play it. 

<video class="cs_hero_video_bg" autoplay muted loop playsinline poster="assets/img/hero_bg_poster.jpg">
  <source src="assets/img/hero_bg_video.mp4" type="video/mp4">
</video>
<button class="cs_hero_video_toggle">…</button>

Colors & Fonts

Brand colors and font families are defined as CSS custom properties on :root in assets/sass/default/_variable.scss. Change them in one place to re-theme the entire template. Font files are declared with @font-face in assets/sass/default/_fonts.scss and base text styles live in _typhography.scss. 

/* assets/sass/default/_variable.scss */
:root {
  --accent-color: #136DF4;     /* primary brand color */
  --primary-color: #1F2937;    /* headings */
  --secondary-color: #4B5563;  /* body text */
  --danger-color: #EF4444;
  --warning-color: #F59E0B;

  --primary-font: 'Montserrat', 'Cairo', sans-serif;   /* headings */
  --secondary-font: 'Open Sans', 'Cairo', sans-serif; /* body */
}

All fonts are self-hosted in assets/fonts/ (no Google Fonts request): Montserrat for headings, Open Sans for body text and Cairo for Arabic. Cairo is loaded with a unicode-range for Arabic glyphs only, so it is downloaded just when Arabic text appears on the page.

No SASS workflow? Because colors are CSS variables, you can override them without recompiling — add a :root { … } block at the bottom of assets/css/style.css (or in your own stylesheet loaded after it).

RTL Support

Hospil supports right-to-left languages such as Arabic out of the box. The same style.css and bootstrap.min.css serve both directions — the layout is built with logical properties and the few LTR-only Bootstrap rules are mirrored in assets/sass/common/_rtl.scss.

Enable RTL

Direction is resolved by directionInit() in main.js, in this order:

  1. A ?dir=rtl (or ?dir=ltr) URL parameter, e.g. index.html?dir=rtl — handy for previewing.
  2. Otherwise the dir attribute on the <html> tag. For a permanent RTL site, set it directly in every page. 
<!-- Permanent RTL (Arabic) site -->
<html lang="ar" dir="rtl">

Language switcher

The header language dropdown (.cs_language_select) switches direction automatically. Buttons whose data-lang is listed in rtlLangs (default ["ara"]) reload the page with ?dir=rtl; every other language reloads with ?dir=ltr, so Swiper, Flatpickr and SplitText re-initialize in the correct direction. 

<button data-lang="ara">ARA</button>   <!-- switches to RTL -->

// assets/js/main.js → languageSwitch()
const rtlLangs = ["ara"]; // add e.g. "heb", "fas", "urd"

Helpers

Helper Use
.cs_ltr Keeps numbers, prices, phone numbers and counters in LTR order inside RTL text (already applied to .odometer and Swiper fraction pagination).
<bdi dir="ltr"> Inline wrapper for short LTR values in running text, e.g. <bdi dir="ltr">+1 444 828 1507</bdi>.
.cs_rtl_flip Mirrors directional icons/images horizontally in RTL.
@include rtl { … } SASS mixin from default/_mixins.scss — outputs [dir="rtl"] .your-selector { … } for RTL-only overrides.
Arabic typography. The Cairo font is already included in --primary-font and --secondary-font, so Arabic content renders correctly without extra setup.

Dark Mode

Hospil includes a complete dark theme that switches on automatically when the visitor's operating system or browser is set to dark mode. It uses the prefers-color-scheme: dark media query, so there is no toggle button, no JavaScript and no extra markup — every page, including RTL pages, adapts on its own.

How it works

All dark styles live in one partial, assets/sass/common/_dark.scss, imported last in style.scss. The light styles are untouched; the partial re-maps the color tokens and overrides only the rules that need it.

  • Tokens re-mapped — --primary-color becomes a light text color, --secondary-color a muted light gray, and the light tint backgrounds (--gray-color … --gray7-color) become deep navy tints.
  • Dark surfaces — new --dm-* tokens (--web-wash, --dm-surface, --dm-surface-2, --dm-border …) are used for page, card and input backgrounds.
  • --white-color stays white, because it is also the text color on accent buttons and image overlays.
  • Logo — img/logo.svg is swapped for the white-text img/logo2.svg automatically.
  • Icons & images — dark SVG icons are lightened with CSS filters (--dm-icon-light / --dm-icon-muted), partner logos are inverted and pastel decoration shapes are toned down.
  • Forms — inputs and Choices.js dropdowns use the dark surface colors. 
/* assets/sass/common/_dark.scss (excerpt) */
@media (prefers-color-scheme: dark) {
  :root {
    color-scheme: dark;
    --web-wash: #0B1220;        /* page background */
    --dm-surface: #111A2E;      /* cards, inputs */
    --dm-surface-2: #17223A;
    --dm-border: rgba(148, 163, 184, 0.16);
    --primary-color: #F1F5F9;    /* headings */
    --secondary-color: #A7B1C2;  /* body text */
  }
}

Preview dark mode

Switch your OS to dark mode, or in Chrome / Edge open DevTools → ⋮ → More tools → Rendering and set Emulate CSS media feature prefers-color-scheme to dark.

Customize the dark colors

Edit the tokens at the top of _dark.scss and recompile. Without SASS, add your overrides at the bottom of assets/css/style.css: 

@media (prefers-color-scheme: dark) {
  :root {
    --web-wash: #000000;
    --dm-surface: #121212;
  }
}

Style your own sections

New sections built with the color variables adapt automatically. For hard-coded colors, add a rule inside the media query in _dark.scss: 

@media (prefers-color-scheme: dark) {
  .my_custom_box {
    background-color: var(--dm-surface);
    border-color: var(--dm-border);
  }
}

Disable dark mode

To keep the site always light, comment out the import in assets/sass/style.scss and recompile: 

// Dark mode (follows device prefers-color-scheme)
// @import "common/dark";
No SASS workflow? Delete the @media (prefers-color-scheme: dark) { … } block (section 33. Dark Mode) near the end of assets/css/style.css.

Cart Drawer (Mini Cart)

On the shop pages (home-v6.html, shop.html, shop-details.html) clicking an Add to Cart button adds the product without leaving the page, shows a confirmation toast and updates the header cart badge. The header cart icon (.cs_cart_btn) opens a slide-out drawer with quantity controls, subtotal and View Cart / Checkout buttons.

  • Add the addToCart class to any button inside a product card (.cs_pharmacy_product, .cs_product_card_1 or .cs_product_summary). Name, price, image and quantity are read from the card's .cs_product_title, .cs_product_price, .cs_product_thumb img and .cs_quantity_input.
  • The cart is stored in localStorage (key hospil_cart), so it persists across pages.
  • Only pages that contain the .cs_cart_drawer markup intercept clicks. On other pages the link simply goes to cart.html. 
<!-- Add the drawer to another page: copy this block from shop.html -->
<!-- Start Cart Drawer -->
<div class="cs_cart_drawer cs_cart_is_empty" aria-hidden="true"> … </div>
<div class="cs_cart_toast" role="status"> … </div>
<!-- End Cart Drawer -->
Front-end demo only. The cart drawer is a client-side UI — connect cart.html / checkout.html to your own e-commerce backend for real orders and payments.

Swiper data attributes

Every .swiper is configured from HTML attributes — no JavaScript editing needed:

Attribute Purpose
data-autoplay, data-loop 1 to enable autoplay / infinite loop
data-speed, data-gap Transition speed (ms) and space between slides (px). Use data-gap="none" for edge-to-edge slides (a plain 0 falls back to the default 24px).
data-slides-per-view A number, or responsive to use data-mobile-slides, data-tablet-slides, data-desktop-slides…
data-marquee 1 for a continuous, linear scrolling ticker (e.g. brand logos)
data-variable-width 1 lets each slide keep its own width (used by the marquee tickers)
data-edge-zoom Edge zone in px (e.g. 70) — slides grow in at one edge and shrink out at the other. Optional data-edge-zoom-out sets the exit scale (default 0.6). Disabled for reduced-motion users.
data-custom-init Skips the generic initializer — used by sliders with their own script (pharmacy hero)

Countdown timer

A .cs_countdown counts down from the values written in its HTML (e.g. <span data-unit="hours">11</span> starts an 11-hour timer). Add data-end to count down to a fixed date instead. If every value is 00, it counts down to the end of the current day ("Deal of the Day"). When time runs out, the element gets the cs_ended class and a "This offer has ended" message is shown. 

<div class="cs_countdown cs_ltr" data-end="2026-12-31T23:59:59">
  <span data-unit="hours">00</span> … <!-- days | hours | minutes | seconds -->
</div>

Interactive section attributes

The physiotherapy and veterinary homes add a few widgets that are switched on by a data attribute on their wrapper. Copy the whole block from the demo page to reuse one elsewhere.

Attribute Purpose
data-inview Adds .is-visible once the element scrolls into view — style the animated state with .your_class.is-visible { … }.
data-painmap Physio pain map: .cs_hotspot buttons (data-target = panel id) open a .cs_painmap_panel; .cs_painmap_view (data-view) toggles front / back.
data-exercise-switch Hovering or focusing a [data-exercise] link swaps the matching [data-exercise-media] preview and the play button's video link.
data-pf-hours Live "Open now / Closed now" status. Each row uses data-days (0 = Sunday … 6 = Saturday, comma separated), data-open and data-close (24-hour, e.g. 8, 17.5).
data-pet-tabs Accessible tabs using role="tab" / role="tabpanel" and aria-controls; arrow, Home and End keys move between tabs (mirrored in RTL). 
<!-- Footer opening hours: Mon–Fri 8:00–18:00 -->
<li data-days="1,2,3,4,5" data-open="8" data-close="18"> … </li>
Please do not edit vendor files unless you have JavaScript experience. Small mistakes can break the scripts — keep your custom code in main.js.
